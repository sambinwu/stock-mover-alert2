## 什么时候会发

所有涨跌幅都是「现价相对上一个收盘价」，报的是现在的数字，不是盘中极值。

| 情况 | 规则 |
|---|---|
| 盘中个股 | 涨跌超 5.5%，并且当天在线外累计待满 30 分钟才发。中途回到线内不清零，回到线外接着算；发的那一刻必须正在线外（Sam 2026-11-17 定） |
| 一天只报一次 | 一只股票提醒过一次，当天就不再提醒：涨得更多不追发，反方向也不报（Sam 2026-11-18 定） |
| 30 分钟一条 | 盘中两条提醒之间至少隔 30 分钟。这中间够格的股票和大盘先攒着，到点那一分钟还在线外的合成一条发；到点时回到线内的，等它下次在线外再发。16:05 收盘那一条不受限制（Sam 2026-11-20 定） |
| 收盘那一条 | 16:05 按 5% 再查一遍：收盘涨跌超 5% 的全部列出来，不管盘中报没报过。只列代码和数字，不带新闻、不 @ 人（Sam 2026-11-17 定）。**收盘没有超过 5% 的就不发**；只有「盘中提醒过、收盘回到 5% 以内」这种情况也不发 |
| 盘前、盘后个股 | 不报，只做盘中（Sam 2026-11-19 定）。收盘后的大动静只在 16:05 那一条里按收盘价体现 |
| 时段 | 个股和大盘只在盘中报；16:05 发收盘那一条。程序 07:00–20:00（美东）醒着 |
| 大盘异动 | 标普 500 和纳指同涨超 1.5%，或同跌超 1%，连续 2 次报价确认；之后每过一档再报一次（大盘不受「一天只报一次」限制） |
| 大盘日 | 比纳指多动不到 3 个点的个股合成一行「跟着大盘动的」，不单独点名 |
| 缓涨缓跌 | 近 5 个交易日累计超 10%、单日都没超 5%，写在收盘那一条里；同一只同方向 7 天内不重复 |
| 补报 | 16:05 那一条当时没发出去的，下次醒来（哪怕是第二天盘前）会补发，标「补报」 |

盘中个股提醒只有一行：股票名、涨跌幅、@ 负责分析师，例如「🔻 *Tempus AI TEM　盘中 -6.0%*　@Kevin」。不带新闻、现价、累计时长、比纳指、财报时间（Sam 2026-11-20 定）。

## 怎么跑的

- **接力，不靠定时器。** GitHub 的定时器经常晚几个小时才启动，这是旧版慢的根源。现在每一轮盯 5 小时 15 分后自己启动下一轮；非监控时段这一轮只是睡着等开盘。
- **交棒失败会自己重试。** 2026-11-25 11:00（美东）交棒时 GitHub 接口连回三次 500/502，旧做法一分钟内试三次就放弃，保险定时器又四个多小时没来，监控停到 14:55。现在启动不了下一轮时，这一轮接着盯盘，每隔 1–5 分钟再试，最多撑 30 分钟；还不行，workflow 最后再试 3 次，然后在 Slack 明说「停了、请手动重启」并给链接。万一重试时起了两轮，晚起的那一轮会自己退出。
- **定时器只当保险。** 每 15 分钟来看一眼，有一轮在跑就立刻退出；没有就重新拉起来，并在 Slack 说一声「中断过，刚恢复」。
- **数据**：Yahoo 报价接口，一次请求拿全部股票，每分钟一次。
- **去重**：发过什么记在 `state` 分支的 `state.json`。先登记、登记成功才发。
- **自己会报的故障**：这一轮运行失败（一天只报第一次）、连续 5 轮拿不到行情、中断后恢复。

## 要改东西时

| 想改什么 | 改哪里 |
|---|---|
| 盯哪些股票 | `watchlist.txt`，一行一只：`代码 中文名 \| 英文关键词`（关键词原来用来找新闻，现在不贴新闻了，留着不碍事）。以美投产品的跟踪清单为准 |
| 提醒时 @ 谁 | 仓库 Settings → Secrets → `OWNERS`，格式 `NVDA:U08XXXX,META:U08XXXX`（Slack 用户 ID）。没列的股票不 @ 人 |
| 阈值、确认次数、时段 | `watch.py` 最上面那一组常量 |
| 发到哪个频道 | Secret `SLACK_WEBHOOK_URL` |

改完代码想马上生效：Actions 里取消正在跑的那一轮，再手动 Run workflow（mode 选 live）。不手动的话，最晚 5 个多小时后的下一轮自动用上新代码。
